If you already use Claude or Cursor, you can connect it directly to one of your academies. The connection lets that assistant browse your courses, read and search lessons, and save edits as drafts without repeated copying and pasting.

<Note>
  This is an optional advanced setup. You do not need it to use Fayne's built-in [lesson AI](/content/ai-customization). The connection standard is called MCP, which is why your AI tool labels this area "MCP" or "Connectors."
</Note>

You choose the academy during sign-in. The connected assistant can work only in that academy. Lesson text changes save to drafts, but deleting lessons or changing the course structure affects the live course immediately.

## What your AI tool can do

After connecting, your assistant gains a set of tools scoped to your academy:

<CardGroup cols={2}>
  <Card title="Browse courses" icon="folder-open">
    List every course in your academy and read a course outline: each lesson's title, order, and length.
  </Card>

  <Card title="Read and search lessons" icon="eye">
    Open any lesson block by block, or run a full-text search across every lesson title and body in a course.
  </Card>

  <Card title="Edit lessons" icon="pencil">
    Make surgical, block-level edits or rewrite a whole lesson. Edits are saved to your draft, never published automatically.
  </Card>

  <Card title="Create and remove" icon="plus">
    Create a new course or lesson, or remove a lesson you no longer need. Plan limits are enforced just like in the dashboard.
  </Card>

  <Card title="Search your knowledge" icon="book-open">
    Ground new content in your own material by searching the sources you have added to your academy's knowledge base.
  </Card>
</CardGroup>

## Before you start

<Steps>
  <Step title="You have a Fayne account with an academy">
    You sign in with your normal Fayne login during setup, then pick which academy to connect. If you manage more than one academy, you choose one per connection.
  </Step>
  <Step title="You use an MCP-compatible AI tool">
    Claude (desktop and web), Claude Code, and Cursor all support remote MCP servers. Other clients need support for remote MCP over HTTP and OAuth. Availability and setup depend on your client and workspace settings.
  </Step>
</Steps>

## The connection URL

Every client connects to the same address:

```text
https://mcp.fayneos.com/mcp
```

There is no API key to copy or paste. The first time your client connects, it opens a browser window where you log in to Fayne and choose which academy to connect. Your client stores the resulting access securely and reuses it on every future request.

## Connect your tool

<Tabs>
  <Tab title="Claude">
    Works in both the Claude desktop app and Claude on the web.

    <Steps>
      <Step title="Open Connectors">
        Go to **Settings \> Connectors** and click **Add custom connector**.
      </Step>
      <Step title="Add the Fayne server">
        Give it a name like `Fayne` and paste the connection URL:

        ```text
        https://mcp.fayneos.com/mcp
        ```

        Click **Add**.
      </Step>
      <Step title="Sign in and pick your academy">
        Claude opens a Fayne sign-in window. Log in, choose which academy to connect, and click **Allow**. The connector now shows as connected.
      </Step>
      <Step title="Use it in a chat">
        Start a new conversation and ask Claude to work with your academy, for example: "List the courses in my academy and summarize the outline of the first one."
      </Step>
    </Steps>
  </Tab>
  <Tab title="Claude Code">
    Add the server from your terminal with the `http` transport:

    ```bash
    claude mcp add --transport http fayne https://mcp.fayneos.com/mcp
    ```

    Then start Claude Code and run `/mcp` to begin authentication. A browser window opens where you log in to Fayne and choose your academy. Once it shows as connected, Claude Code can call the Fayne tools directly.

    <Tip>
      Add `--scope project` to share the connection with your team through a checked-in `.mcp.json`, or `--scope user` to make it available across all of your own projects. Each teammate still signs in with their own Fayne account.
    </Tip>
  </Tab>
  <Tab title="Cursor">
    <Steps>
      <Step title="Open MCP settings">
        Go to **Settings \> MCP** and click **Add new MCP server**.
      </Step>
      <Step title="Add the Fayne server">
        Add Fayne as an HTTP server. In your `mcp.json`, that looks like:

        ```json
        {
          "mcpServers": {
            "fayne": {
              "url": "https://mcp.fayneos.com/mcp"
            }
          }
        }
        ```
      </Step>
      <Step title="Sign in and pick your academy">
        Cursor prompts you to authenticate. A browser window opens where you log in to Fayne and choose your academy. The server then shows a green dot in MCP settings.
      </Step>
    </Steps>
  </Tab>
</Tabs>

<Note>
  One connection is scoped to one academy. To work with a second academy, add a second connection and choose that academy when you sign in.
</Note>

## How edits stay safe

Letting an AI tool write to your live academy sounds risky, so Fayne builds in guardrails.

<CardGroup cols={2}>
  <Card title="Review lesson drafts" icon="file-pen">
    Lesson text changes save to drafts for you to review and publish. Deleting a lesson or reorganizing modules changes the live course, including the order used for drip availability.
  </Card>

  <Card title="Conflict protection" icon="shield-check">
    Fayne checks for concurrent changes during a lesson save. Ask your assistant to read immediately before editing, avoid editing the same lesson in two places at once, and have it re-read before retrying a conflict.
  </Card>

  <Card title="Scoped access" icon="lock">
    A connection can only touch the single academy you chose at sign-in. It cannot see your other academies or any other owner's content.
  </Card>

  <Card title="Plan limits enforced" icon="gauge">
    Creating courses and lessons respects the same plan limits as the dashboard. Write requests are limited to 100 per 60 seconds per credential. A locked academy remains read-only.
  </Card>
</CardGroup>

## Tips for good results

- **Ask it to read before it writes.** "Read lesson 3, then tighten the introduction" produces better edits than asking blind. Your tool is built to read first, but naming the lesson helps it target the right one.
- **Point it at your knowledge base.** If you have added sources to your academy, ask the assistant to ground a draft in them: "Draft a lesson on discovery calls using my frameworks."
- **Use the built-in prompts.** Most clients surface Fayne's ready-made prompts (draft a lesson, critique a lesson, expand an outline) in their prompt or slash-command menu.
- **Review before publishing.** Open the lesson in the Fayne editor, read the AI's changes, and publish when you are happy. The [block editor](/content/block-editor) shows exactly what changed.

<Note>
  Lessons you add from the Explore Library become your academy's own copies. Edits made through a connected tool change your copy only, never the Explore Library or any other academy. See [Explore Library](/content/course-library) for how copies work.
</Note>

## Troubleshooting

<AccordionGroup>
  <Accordion title="The browser sign-in window never appears">
    Your client may have cached a failed attempt. Remove the Fayne server from your client and add it again. In Claude Code, run `claude mcp remove fayne` and re-add it, then run `/mcp` to retry authentication.
  </Accordion>

  <Accordion title="The tool says it cannot find my course or lesson">
    Connections are scoped to a single academy. Confirm you chose the right academy during sign-in. If you picked the wrong one, remove the connection and add it again, then select the correct academy.
  </Accordion>

  <Accordion title="My edits are not showing up for students">
    Lesson text changes are saved as drafts. Open the lesson in the Fayne editor and publish it. Deletion and course-structure changes take effect immediately.
  </Accordion>

  <Accordion title="I get a rate limit or plan limit error">
    Write requests are limited to 100 per 60 seconds per credential, and course and lesson creation respects your plan limits. For a rate limit, wait for the interval shown in the error. For a plan limit, review your usage in Fayne.
  </Accordion>
</AccordionGroup>

## Example requests

Use course and lesson names from your own academy:

- "Show me the courses in my academy."
- "Create a draft course called Client Onboarding with exactly three lessons. Reuse the initial blank lesson."
- "Read the Attribution lesson in Marketing Metrics, then add a Common mistakes section without removing the existing content."
- "Group all lessons in Marketing Metrics into Acquisition and Measurement modules without deleting any lessons."
- "Find how I explain customer acquisition cost in my other courses."
- "Search my knowledge sources for the client discovery framework, then read the matching source."

Creating a course also creates one blank lesson. Ask your assistant to reuse it when you want an exact lesson count.

## What the connection can access

The assistant can read course outlines, module titles, lesson content, course-page descriptions and authoring-enabled knowledge sources in the academy you authorize. Responses include the identifiers and authoring details needed to locate and edit that content. Source reads may be shortened when a document is long.

The connector has no tools for member records, learner practice responses, payment records, pricing settings or deleting whole courses. Personal information you put in course text or knowledge sources can still be returned to your connected assistant. Only enable a source for authoring when you want it available for these workflows; see [Knowledge](/content/knowledge).

Fayne records activity information for security and support, including the tool called, time, outcome and request metadata. Existing logs can include course titles and search terms. Your assistant provider processes the content it receives under its own privacy policy. See [Fayne's privacy policy](https://fayneos.com/legal/privacy) for Fayne's data-handling and retention terms.

## Disconnect or revoke access

Remove the Fayne connection in your assistant's settings to stop using it there. Removing a connection does not delete content the assistant provider has already retained.

If you use a headless access token, revoke that token in Fayne's **Settings > MCP server**. This token list does not manage OAuth connections. To request server-side revocation of an OAuth grant, contact [Fayne support](/support); include the connected assistant and academy name, but never send an access token or password.

## Get help

For setup problems, missing courses, failed edits or access-revocation requests, visit [Fayne support](/support). Include the assistant name, approximate time and error message, without private lesson content or credentials.
